# PK-DoH-2026: website fingerprinting on encrypted DNS, revisited

Code, data and paper source for **"Does Encrypted DNS Still Hide Visited Websites? Reproducing a 2020 Fingerprinting Attack and Testing It from Pakistan Against Deployed Padding"** (Muhammad Kaif and Samran Ahmad, FAST-NUCES Islamabad, Computer Networks research project, 2026).

The study:
1. reproduces the DoH website-fingerprinting attack of Siby et al. (NDSS 2020) on the authors' released data;
2. collects **PK-DoH-2026**, 1,998 Chrome 157 page loads of 100 websites (50 Pakistani) captured in Pakistan against a resolver that pads (Cloudflare) and one that does not (Quad9);
3. audits the EDNS(0) padding of 11 public DoH/DoT resolvers;
4. evaluates five baselines and two proposed models, with transfer, recovery and ablation experiments.

## Key results

| | Macro-F1 |
|---|---|
| Reproduction of Siby et al., LOC1 (published 0.898) | 0.893 |
| Original attack in 2026, Quad9 (no padding) | 0.948 |
| Original attack in 2026, Cloudflare (468-byte padding) | 0.342 |
| Proposed fused random forest, Cloudflare | 0.444 |
| 2018 model tested on 2026 traffic | at chance (≤ 0.004) |

## Repository layout

| Folder | Contents |
|---|---|
| `code/` | All Python code: experiments, models, features, padding audit, figures |
| `code/capture/` | Crawler (`collect.py`), pcap-to-trace extractor (`extract.py`), site list (`sites.csv`) |
| `data/traces/` | **PK-DoH-2026**: one JSON line per page visit (signed TLS record sizes, timestamps, metadata) |
| `data/pcap/*_meta.csv` | Per-visit crawler metadata (status, page title, timing) |
| `results/` | Every result file behind the tables and figures (JSON, CSV, logs) |
| `figures/` | All figures (300 dpi PNG) |
| `paper/` | LaTeX source of the paper (Springer Nature `sn-jnl` template) |
| `report_builder/` | Scripts that build the Phase 3 report (docx and LaTeX) from `results/` |

Site ids: global sites are `G00`–`G49`; Pakistani sites are `P00`–`P49` in the data and `PK00`–`PK49` in the paper.

Not included: the raw packet captures (316 MB; `data/traces/` holds everything the experiments use) and the 2018–19 datasets of Siby et al. (9.4 GB), which are available from <https://github.com/spring-epfl/doh_traffic_analysis>. To rerun the reproduction, clone that repository into `baseline_siby/` next to `code/`.

## Requirements

- Python 3.12+ with numpy, pandas, scipy, scikit-learn, torch (CPU), matplotlib, psutil, httpx[http2], certifi, dnspython, selenium
- Wireshark/tshark with dumpcap, and Chrome with the matching ChromeDriver (only for collecting new traces)
- Node.js with the `docx` package (only for the Phase 3 report builder)

## Reproducing every table and figure

Run from `code/`, in this order:

1. `python capture/extract.py` turns pcaps into `data/traces/*.jsonl` (skip this step and use the included traces).
2. `python padding_audit.py` runs the resolver padding audit.
3. `python run_e1_queue.py` reproduces Siby et al. on their data. Each row is `python e1_reproduce.py <experiment> <samples> all <folds>`, and finished folds are skipped. This step takes about 4 hours on a 16-thread laptop.
4. `python experiments.py realism e2 e5 e3 e4 ablate siby_baselines siby_cross` runs all other experiments.
5. `python report_data.py`, then `python figures.py` and `python fig_pipeline.py`, regenerate the figures.
6. The paper: compile `paper/main.tex` with pdfLaTeX inside the Springer Nature LaTeX template, which provides `sn-jnl.cls` and the bibliography styles.

All splits use `random_state=0`, and model seeds equal the fold or split index.

To collect new traces, run one process per resolver address:

```
python capture/collect.py --resolver cloudflare --ip-index 0 --stride 4 --network wifi --iface <n> --rounds 10
```

## Ethics

All traffic was generated by the authors' own crawler on their own machine, sent to public resolvers they selected. No third-party, institutional or user traffic was captured.
